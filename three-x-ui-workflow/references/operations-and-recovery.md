# 运维、故障、备份与恢复

## 1. 分层诊断，不先重装

先保存失败输入与输出，找能复现用户症状的请求，再选择检查层：

| 症状 | 优先检查 | 不能直接下的结论 |
|---|---|---|
| 面板完全打不开 | 地址/端口/根路径、DNS、TLS、监听、云/主机防火墙、外部路由 | 不等于服务一定停止 |
| 只有一台电脑打不开 | 系统/应用代理、TUN、路由、物理网络对照 | 关闭代理 UI 不等于 TUN 路由消失 |
| 端口可达但连接失败 | 身份关联、协议、密钥、SNI/目标、flow、时钟、核心版本 | 不等于一定被封锁或必须换密钥 |
| 新入站没有客户端 | 确认独立/共享身份意图，再用该版本受支持入口关联 | 不要默认把所有用户附加进去 |
| 连接成功但很慢 | 供应商剩余额度、客户端/入站额度、CPU/内存、路径双向质量 | 不等于运营商全局故障 |
| API 写操作超时 | 查对象、实际配置及请求日志，确认是否已成功 | 不要直接重试造成重复创建 |
| 升级后旧用户失败 | 迁移说明、有效配置、版本门槛、旧协议支持 | 新核心进程启动不等于回归通过 |

`curl --noproxy` 只能影响应用代理选择，不能保证绕过 TUN 或系统路由。Windows 可只读使用 `Find-NetRoute -RemoteIPAddress <HOST>`（须先解析出目标 IP）、`Get-NetAdapter` 等；接口名称必须现场发现，不写死。禁用某接口、增加路由、改变防火墙均属单独网络变更，先确认远程失联影响与恢复方法，不一键清网络。

重装系统、流量重置、升级面板和更换协议是不同动作。不要把“重装”当恢复供应商流量额度的方法，也不要为排查节点而处理其他服务。

## 2. 私密备份集合

备份前发现实际目录/挂载与数据库引擎，记录当前面板版本、核心版本、二进制/镜像引用、服务/编排定义、面板设置、证书及私钥、订阅设置、数据库、网络规则与相关 DNS。把恢复步骤与校验和一起保存到受限目录，并有离机恢复点。

**一致性要求：**若实例使用 SQLite，运行中直接复制一个 `.db` 文件不能保证包含 WAL/并发事务。优先用该版本面板支持的一致性导出或 SQLite online backup；若必须冷备，安排维护窗口并确认没有其他写入者，再按实际存储布局复制完整集合。容器“复制卷”也不自动保证数据库一致。

不在通用文档中预填服务名、数据库绝对路径、容器 ID、备份位置或密码。权限依操作者 OS 与身份设置；不要为了方便让备份变成全员可读。

## 3. 升级/迁移门禁

1. 明确升级目标，不自动追 `latest`；读取当前→目标的发布说明、数据库迁移与协议兼容差异。
2. 验证备份能读取且可在隔离副本恢复，保留旧面板/核心二进制或固定镜像、相容配置和启动定义。
3. 记录基线请求与关键旧节点，防止同时有 UI、API、脚本写配置。
4. 按当前安装方式升级；原生与 Docker 不混用。迁移到另一种方式是单独任务，不是普通升级副作用。
5. 校验目标版本、数据持久化、管理入口、真实节点请求和既有用户回归。
6. 不通过时保留日志并判断是否回退。只换回旧二进制未必兼容新数据库：按迁移说明恢复**同一恢复点**的数据库、程序、配置/卷和证书集合。

## 4. 两种不同的“回滚已验证”

- **本地候选/隔离副本回滚**：恢复独立副本，比较原始 hash，运行相同命令和输入。证明副本可恢复，不触碰线上。
- **生产服务回滚**：需要维护窗口、单独批准、全套相容恢复点及失联恢复通道。恢复后还须验证启动、监听、认证、HTTPS 请求、旧节点及数据库状态。

不为证明“能回滚”而打断生产。没有线上演练时写“未演练”，不要用文件 hash 或静态解析冒充服务恢复成功。恢复失败时停止反复尝试，保留残余状态并升级给操作者。

## 5. 交接及发布

用 [交接模板](../templates/handoff.md) 记录目标、范围、授权、状态、实际命令、时间、退出码、关键输出、备份/回滚范围、下一步。新 AI 先读取最后确认状态，再回读最小必要对象，从第一个未完成操作继续，不重复已完成的安装或创建。

证据分两层：

- 私密层：完整必要配置、原始日志、备份、凭据引用，限制权限并约定保留期。
- 可公开层：模板、脱敏症状与判定、非敏感测试结果，不含实际主机身份/面板根路径、账号、UUID、订阅 ID、Cookie、令牌、证书私钥、数据库或二维码。

发布只暂存明确 allowlist 的文档/脚本/模板，检查 Git staged diff 和历史新增对象；不要上传整份工作目录、下载目录、日志目录或服务器导出。敏感数据若已进入公开 Git 历史，删除当前文件并不足够：停止发布、撤销相关凭据、按平台流程清理历史并通知操作者。

## 6. 脱敏故障示例

某入站已启用但没有有效客户端。补建独立身份后，HTTPS 请求仍未得到响应；检查实际核心版本与日志后，经操作者批准只调整该入站的兼容边界，相同请求才通过。

可复用的是“分别验证身份与兼容性、只改单一目标、保留前后证据”，不是当时的主机、版本、域名、凭据或最低版本数值。相同错误文字也不能当作唯一根因。
