# 验收、排错与回滚

本卡是执行检查表，不是“已通过”的报告。发布或接入某个项目时，应记录当次真实结果；不能把之前的 R15 样例成功套用到所有 Rig。

当前发布的实测范围见[本版本验证范围](validation-scope.md)，未覆盖项不能套用为通过。

## 一、修改前记录

至少保存以下可恢复的信息，项目/物品副本与当前操作对象应分开：

| 内容 | 记录什么 |
|---|---|
| 对象身份 | 容器、完整实例路径、Accessory/Tool 类型、唯一 Handle |
| 模板状态 | 备份文件或复制对象；有文件时记录 SHA-256 |
| 校准字段 | Tool.Grip；已有校准标记/Accessory Attachment 的名字与 CFrame |
| 原有行为 | 修改前装备/穿戴结果；已有动作是否正常 |
| 发放归属 | 使用哪个模板、OwnerId/RecipeId、会替换哪一类既有物品 |

工作台会记录本轮初值用于“恢复本次初值”，但它不是跨重启备份。需要长期回滚时保留独立模板副本与项目版本。

## 二、按层验证

| 层级 | 应检查什么 | 不能据此声称什么 |
|---|---|---|
| 离线 | 文档链接、Luau 编译、相对变换、恢复、错误输入 | 不等于 Studio 已安装/已装备 |
| Studio Edit | 选择绑定正确、预览可移动旋转、保存字段一致、原件尺寸不变 | 不等于运行时姿态正确 |
| 真实 Play | 穿戴/装备、跟随、碰撞、停止后数据保留 | 不等于多人、全部体型兼容 |
| 实际交互 | Prompt 按键后发给正确玩家、去重、拒绝非法条件 | 直接调用 Equip 不等于按键拾取通过 |
| 持久性 | 保存、重新打开后校准保留；插件重新加载 | 当前会话有按钮不等于冷启动通过 |

### Accessory 最低通过条件

- 身体目标点实际存在，Handle 内同名点与其对齐。
- AddAccessory 后有有效连接，核对连接端点与挂点世界位置/朝向误差，物品外观与预览相符；不要固定只寻找名叫 AccessoryWeld 的对象，目标 Studio 可能使用刚性约束。
- 玩家走、转身、跳跃不被物品固定；无关饰品保留。

### Tool 最低通过条件

- 源模板 Grip 更新，标记若存在则与保存值一致。
- 真实背包装备后的握持关节连接实际 RightHand 与本 Tool.Handle；C0 与身体 RightGripAttachment.CFrame 相同，C1 与 Tool.Grip 相同，记录两侧世界位置/朝向误差。
- 收起/重装后重新检查；只在初次 Equip 时对齐一次，不等于后续自动重建的关节仍正确。
- 观察原生关节延迟生成时的有界等待、明确超时失败；不能把 EquipTool 返回或 Parent 变更当作姿态已对齐。
- 多零件不散开；已有动作若测试，应单独记录结果。

### 工作台最低通过条件

- 移动与旋转都触发校准；关闭自动同步后直到点击保存才改模板。
- “从模板刷新”读取已保存姿态；“恢复本次初值”恢复本轮原值。
- 原 Rig/模板世界位置、比例不被预览创建擅自修改。
- Play 时暂停校准、游戏中没有编辑假人；Stop 后人工姿态仍在。
- 结束预览不删除真实模板，也不意外撤销已保存字段。
- 撤销/重做应在目标 Studio 版本中另测；不要仅因代码用了 ChangeHistoryService 就承诺一次撤销全部操作。

## 三、故障按这个顺序查

1. **选错对象**：查看工作台显示的源模板与目标挂点；是否选择了 Visual、运行时副本或另一个同名物品。
2. **结构不对**：容器是否真为 Accessory/Tool；Handle 是否唯一且直接；目标点是否在身体部位下。
3. **数学不对**：是否以 Handle 世界 CFrame 为基准；是否把本地变换当世界值；矩阵乘法顺序是否反了。
4. **被其他逻辑覆盖**：项目是否每次创建 Tool 后重写固定 Grip；自定义动画/握持系统是否改变关节合同。
5. **物理不对**：运行时任一零件是否仍 Anchored、残留外部 Weld/Constraint、出现碰撞阻挡。
6. **运行条件不对**：看服务器 Output 的具体错误；确认模块引用、模板类型、Prompt 归属与距离/冷却。

不要用全局关闭碰撞、删光饰品、硬编码玩家名或反复改随机 Grip 数值掩盖原因。

## 四、回滚与复验

1. 在编辑模式停止同步，保留当前结果副本；本轮内可点 **恢复本次初值**。
2. 跨会话恢复时，用备份模板替换明确指定的副本，或恢复记录中的 Grip/Attachment CFrame；原来没有的新校准标记也应移除。
3. 结束临时预览。要停用编辑器，用 Studio 管理插件；不能只删游戏里的预览模型却声称卸载了本地插件。
4. 用与基线相同的角色、输入和装备流程重新 Play，核对恢复行为；文件级回滚再核对原始哈希。
5. 验证回滚应在副本进行，避免把用户最新满意的校准结果覆盖掉。完成后确认当前交付保留的是修改版还是回滚版。

## 五、交接记录模板

```text
分支：Accessory / Tool / 拾取
源模板、Rig、目标挂点：
修改字段与备份：
BASELINE：命令/输入、观察、Output 原文或截图
MODIFIED：同输入、观察、Output 原文或截图
ROLLBACK：恢复方式、同输入、观察、哈希（若适用）
已验证：
未验证：其他 Rig / 多人 / 动作 / 撤销重做 / 重启加载等
当前保存状态：模板已写入 / 项目已保存 / 插件已安装或已加载
```

记录在项目自己的测试/交接位置，不把玩家标识、私人路径或运行日志提交到公开 Skill 仓库。
